Geração Matemática do Segredo Pré-Mestre Compartilhado K
Sem transmitir segredos pela rede, ambos calculam o mesmo $K = B^a \pmod p = A^b \pmod p = g^{ab} \pmod p$. O bisbilhoteiro só interceptou $A$ e $B$, sendo incapaz de computar $K$.

Matemática do Diffie-Hellman DISCRETE LOG PROBLEM
Teoria dos Números & Exponenciação Modular:
Parâmetros Públicos: Base $g = 5$, Módulo Primo $p = 23$
Cliente gera segredo privado $a = 6 \implies A = 5^6 \pmod{23} = 8$
Servidor gera segredo privado $b = 15 \implies B = 5^{15} \pmod{23} = 19$
Ambos derivam o mesmo segredo $K$:
Cliente: $K = 19^6 \pmod{23} = 2$ | Servidor: $K = 8^{15} \pmod{23} = 2$

Guia Prático da Bancada — O Que Esperar e Como Testar

Módulo 1: Injeção SQL & Árvore Sintática (AST)

O Cenário Real: Um sistema de login vulnerável concatena a entrada do usuário diretamente na string SQL: SELECT * FROM users WHERE user = '" + input + "'.

Passo 1: O Ataque (Tautologia)

1. Mantenha em Modo Vulnerável.
2. Clique no preset ' OR '1'='1' -- e depois em Executar Query.
3. O que esperar na tela: A Árvore AST ganha um nó vermelho OR TRUE. O Mock DB retorna todas as 5 contas do banco com senhas e salários expostos!

Passo 2: A Blindagem (Prepared Statement)

1. Alterne para Modo Seguro (Prepared Statement).
2. Clique novamente em Executar Query.
3. O que esperar na tela: A query usa placeholder WHERE username = ?. O banco trata ' OR '1'='1' como literal de texto, a AST fica azul/verde e retorna 0 linhas (Acesso Negado)!

💡 Conceito-Chave para Entrevistas: Prepared Statements separam o código dos dados no nível do compilador do SGBD, impossibilitando que dados de entrada alterem a gramática da instrução.
Módulo 2: Cross-Site Scripting (XSS) & CSP

O Cenário Real: Um fórum ou rede social exibe comentários de usuários usando innerHTML sem sanitizar tags HTML ou caracteres especiais, permitindo execução arbitrária de JavaScript.

Passo 1: O Ataque (Roubo de Sessão)

1. Desmarque as opções de Sanitização e CSP.
2. Clique no preset <script>stealSession(document.cookie)</script> e clique em Submeter / Injetar.
3. O que esperar na tela: Um modal vermelho "Exfiltração C2 Detectada" surge instantaneamente mostrando o cookie de sessão e token JWT sendo roubados para o servidor do invasor!

Passo 2: Defesa em Camadas (Encoding + CSP)

1. Ligue Sanitização: Caracteres perigosos viram entidades HTML (&lt;script&gt;) e o texto é exibido inofensivo na tela.
2. Ligue CSP (Content-Security-Policy): O cabeçalho script-src 'self' impede a execução de scripts inline; o navegador bloqueia a injeção e emite relatório de violação!

💡 Conceito-Chave para Entrevistas: Cookies com flag HttpOnly não podem ser lidos via JS, e políticas de CSP estritas bloqueiam scripts inline mesmo se a sanitização falhar.
Módulo 3: Handshake TLS 1.3 & Sniffer de Pacotes

O Cenário Real: Um usuário envia credenciais bancárias pela rede Wi-Fi de uma cafeteria onde um atacante está rodando um sniffer (Wireshark) interceptando todo o tráfego.

Passo 1: Sniffer em HTTP Aberto

1. Observe o botão de alternância HTTP vs HTTPS.
2. Em HTTP, veja a raia central do Sniffer: qualquer atacante na mesma rede lê a requisição POST /login password=sandro123 em texto puro sem qualquer esforço!

Passo 2: Handshake TLS 1.3 Criptográfico

1. Clique em Iniciar Handshake TLS 1.3.
2. O que esperar na tela: 5 fases são executadas com pacotes voando na tela. Cliente e Servidor usam Diffie-Hellman Efêmero para calcular o mesmo segredo compartilhado (K=2) e derivar chaves AES-GCM.
3. O Sniffer passa a enxergar apenas ruído criptográfico: 0x7a8f2b... [ENCRYPTED DATA]!

💡 Conceito-Chave para Entrevistas: TLS 1.3 garante Perfect Forward Secrecy (PFS) via ECDHE: mesmo se a chave privada do servidor vazar no futuro, comunicações passadas gravadas não podem ser decifradas.
Módulo 4: JWT Inspector & HMAC-SHA256 Real

O Cenário Real: Uma aplicação confia no JSON Web Token (JWT) enviado pelo cliente para conceder permissões administrativas de sistema sem validar a assinatura criptográfica no backend.

Passo 1: Fraudar Privilégio & Bypass alg: none

1. No editor de Payload (roxo), clique no preset Tornar 'admin'.
2. O que esperar na tela: O badge de integridade vira vermelho: ASSINATURA VIOLADA (TAMPERED)! O servidor detecta que o payload mudou.
3. Clique em Bypass alg: none: o token tem a assinatura removida, demonstrando o clássico exploit onde bibliotecas antigas aceitavam tokens sem conferir assinatura.

Passo 2: Brute-Force de Segredos Fracos

1. Mude o Segredo do Servidor para secret.
2. Clique em Testar Dicionário de Chaves.
3. O que esperar na tela: A Web Crypto API testa uma wordlist em milissegundos e quebra a chave fraca, provando por que segredos devem ter alta entropia (≥ 256 bits).

💡 Conceito-Chave para Entrevistas: JWTs são codificados em Base64URL, não encriptados. Qualquer um pode ler o conteúdo; a segurança reside exclusivamente na verificação da assinatura criptográfica no backend.
Módulo 5: Hashing, Salting & Força Bruta

O Cenário Real: Uma empresa sofre um vazamento de banco de dados (data breach). Como as senhas dos colaboradores estavam guardadas determina se todos os logins serão quebrados em segundos ou se permanecerão blindados por séculos.

Passo 1: O Risco de Hashes Sem Salt (Caso A)

1. Veja o painel Caso A: Sem Salt.
2. Mariana e Roberto têm a mesma senha ("senha123"). Seus hashes SHA-256 são rigorosamente idênticos.
3. O que esperar: O atacante percebe o padrão e usa uma Rainbow Table pré-calculada para descobrir ambas as senhas em 1 milissegundo.

Passo 2: Salt Criptográfico & Bcrypt (Caso B)

1. Clique em Regenerar Salts Aleatórios no Caso B.
2. Cada usuário recebe 16 bytes aleatórios antes da senha: os hashes ficam completamente diferentes.
3. Clique em Rodar Benchmark (10.000 Hashes): veja a CPU do seu navegador calcular milhares de SHA256 em microssegundos, e confira na tabela por que o Bcrypt (lento por design) exige > 2.300 anos para ser quebrado em GPU!

💡 Conceito-Chave para Entrevistas: Funções de hash velozes (SHA-256) foram criadas para integridade de arquivos, não senhas. Para senhas, são mandatórios algoritmos com fator de trabalho iterativo (KDF) como Bcrypt, Argon2id ou PBKDF2.
